# Dashboard Tab Guide

The AdventureWorks Analytics Platform dashboard combines business analytics, machine learning predictions, and sales forecasting in one browser interface.

Open the dashboard at:

```text
http://localhost:8000/
```

## Tableau Dashboard

### Purpose

This tab displays an embedded Tableau dashboard for exploring sales data through interactive business intelligence visualizations.

### What You Can Do

- Review high-level sales performance.
- Explore Tableau charts, filters, and dashboards.
- Compare business results visually.

### Important Note

The embedded Tableau dashboard requires access to its configured Tableau URL. If it does not load, the external dashboard may be unavailable or blocked by the network.

## EDA Summary

EDA means **Exploratory Data Analysis**. This tab provides an overview of the cleaned sales dataset.

### What It Shows

- Dataset summary statistics.
- Monthly sales trend.
- Sales totals grouped by region.
- Region sales table.
- Top-selling products chart.
- Top customers chart.

### How It Works

The displayed summary and charts are generated by:

```bash
python3 -m app.api.services.eda_pipeline
```

The command creates files inside `outputs/eda/` and saves the cleaned dataset to `data/processed/merged_sales_data.csv`.

### How to Interpret It

Use this tab to understand the dataset before making predictions:

- Monthly sales show how revenue changes over time.
- Region totals show which sales territories perform best.
- Top products identify the strongest products.
- Top customers identify customers with the highest historical sales.

## Interactive Analysis

### Purpose

This tab lets you create custom grouped sales analyses without writing Python or SQL.

### Inputs

- **Group data by**: selects the dimension used to organize results, such as category, product, customer, month, or channel.
- **Metric**: selects the calculation to perform.
- **Rows to show**: controls how many top results appear.
- **Country filter**: limits the analysis to selected countries.
- **Category filter**: limits the analysis to selected product categories.
- **Channel filter**: limits the analysis to Internet or Reseller sales.

### Available Metrics

- Total sales amount
- Average sales amount
- Total order quantity
- Number of order lines

### Outputs

- A short analysis summary.
- A bar chart.
- A result table.

### Example

To find the strongest product categories in Australia:

1. Select `category` for **Group data by**.
2. Select `Total sales amount` for **Metric**.
3. Select `Australia` in the country filter.
4. Click **Run analysis**.

## Buy / Not Buy Prediction

### Purpose

This tab uses a Random Forest classification model to estimate whether a selected customer is likely to buy a selected product.

### Inputs

- **Customer**: searchable customer list.
- **Product**: searchable product list.
- **List price**: product list price.
- **Country** and **State / province**: customer location.
- **Category**, **Subcategory**, and **Color**: product attributes.
- **Channel**: Internet or Reseller.

Selecting a customer automatically fills known customer attributes. Selecting a product automatically fills known product attributes.

The model also receives a hidden sales territory derived from the selected country and state.

### Outputs

- **Prediction**: `Buy` or `Not Buy`.
- **Probability of Buy**: model confidence between `0` and `1`.

### How to Interpret It

A result such as:

```text
Prediction: Buy
Probability of Buy: 0.810
```

means the model predicts a purchase with an estimated probability of 81%.

This is a model estimate based on historical data, not a guarantee of customer behavior.

The dataset contains purchases but no explicit Not Buy records. During training, unobserved customer-product pairs are sampled as synthetic Not Buy examples. Order quantity is intentionally excluded because it is normally unknown before purchase and would leak information about the result.

## Sales Prediction

### Purpose

This tab estimates the sales amount for a possible transaction.

### Inputs

- **Customer** and customer location.
- **Product** and product attributes.
- **Order quantity**.
- **Unit price**.
- **Discount percentage**, from `0` to `1`.
- **List price**.
- **Channel**.
- **Month** and **Fiscal quarter**.

Customer and product selections automatically fill related fields. The sales territory is derived internally and remains hidden.

### Output

- **Predicted sales amount**

### Prediction Method

The output comes from the trained Random Forest Regressor saved in `models/random_forest_regressor.joblib`. Quantity, price, and discount are model features, but the application does not directly calculate the output with a sales formula.

Use this tab for transaction-level what-if analysis, such as testing how different quantities, prices, discounts, customer attributes, and product attributes affect the model prediction.

## Future Sales Forecast

### Purpose

This tab predicts future monthly sales using historical monthly sales patterns.

### Inputs

- **Product**: optionally forecast one product.
- **Region**: optionally forecast one sales territory.
- **Forecast Horizon**: number of future months to predict, from 1 to 24.

Leave product or region empty to forecast a broader sales total.

### Outputs

- Predicted sales for the next month.
- Predicted combined sales for the next quarter.
- Monthly forecast table.
- Forecast line chart.

### How It Works

The forecasting service:

1. Groups historical sales by month.
2. Creates features from the previous three months.
3. Trains a Random Forest regressor.
4. Predicts future months one at a time.

If a selected product or region has too little history, the service uses average historical sales as a fallback.

### How to Interpret It

Forecasts are useful for planning and identifying likely trends. They should not be treated as guaranteed future revenue because unexpected business changes are not represented in historical data.

## Suggested Student Learning Path

Use the tabs in this order:

1. Review the **EDA Summary** to understand the data.
2. Use **Interactive Analysis** to answer business questions.
3. Try **Buy / Not Buy Prediction** to explore classification.
4. Try **Sales Prediction** to explore Random Forest regression.
5. Use **Future Sales Forecast** to study time-based predictions.
6. Compare the application dashboard with the **Tableau Dashboard**.

## Common Terms

| Term | Meaning |
| --- | --- |
| Country | Customer's country |
| State / province | Customer's state or province |
| Sales territory | Internal AdventureWorks sales area derived from location |
| Channel | How the sale occurred: Internet or Reseller |
| Category | High-level product group |
| Subcategory | More specific product group |
| Classification | Predicting a label, such as Buy or Not Buy |
| Regression | Predicting a continuous value, such as transaction sales amount |
| Forecasting | Predicting future values using historical time-based data |

For a detailed explanation of the three machine learning tasks and the synthetic Not Buy class, read [`ML_METHODOLOGY.md`](ML_METHODOLOGY.md).
